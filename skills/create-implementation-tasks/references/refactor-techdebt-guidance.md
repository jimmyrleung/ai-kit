# Additional guidance for refactor / tech debt work

Follow these instructions when working on a refactor/tech debt (reestructuring, consolidating, eliminating tech-debt, etc. - any work that indicates no new capability)

## Design approach

For refactor/tech-debt, we should consider both **pragmatic-balance** and **clean-architecture**

Launch separate subagents to explore the different design approaches when in doubt of which one would be better.
